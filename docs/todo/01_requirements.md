# TODOアプリ V1 要件定義書

## 1. 目的・対象範囲

- 背景・課題：やることをメモやチャットで管理すると、抜けや完了の確認漏れが出る。
- 目的：1か所で TODO を一覧し、登録・完了・削除ができるWebアプリを作る。授業課題として、REST API・Fetch・Neon(PostgreSQL)・Vercel の一連の流れを理解する。
- 対象者：学生本人（1人利用）。認証は V1 では作らない。
- 利用環境：PC のブラウザ（スマホ対応は対象外）。
- 実装環境：既存の Express + TypeScript + EJS サイト。DB は学生自身の Neon PostgreSQL、公開先は Vercel。
- 既存の `/`（トップ）と `/api/db-check` は残す。TODO 画面は `/todo` に置く。
- DB 接続は既存の `db.ts` と `DATABASE_URL` を使う。
- Preview と Production は同じ Neon DB を参照する。架空の授業用データだけを使い、個人情報は入力しない。

## 2. 機能要件

REST API は `/api/todo/v1/todos` とし、GET・POST・PATCH・DELETE の4操作を対象とする。画面からは Fetch で API を操作する。

### REQ-01 TODO 一覧を取得する
- 操作：`/todo` を開く／`GET /api/todo/v1/todos`
- 入力：なし
- 結果：200 で `{ "data": [ ... ] }`。0件のときは `data: []`。
- エラー：DB エラー 500、DB 接続不可 503。
- 受け入れ条件：データ0件なら GET の data が空配列になり、画面に「TODOがありません」と表示されること。
- 確認方法：ブラウザで `/todo` を開く。`/api/todo/v1/todos` を直接開いて JSON を見る。

### REQ-02 TODO を登録する
- 操作：入力欄にタイトルを入れて追加／`POST /api/todo/v1/todos`
- 入力：`{ "title": "..." }`。title は前後の空白を除いて 1〜100文字。
- 結果：201 で作成した TODO を `{ "data": { ... } }` で返す。完了状態の初期値は未完了。
- エラー：本文が不正 400、title が制約違反 422、500、503。
- 受け入れ条件：有効なタイトルで追加すると一覧に未完了で現れ、空文字や101文字以上では追加されずエラーが表示されること。
- 確認方法：画面から追加する。空欄・空白のみ・101文字で追加して拒否されることを見る。

### REQ-03 完了状態を変える（部分更新）
- 操作：チェックを切り替える／`PATCH /api/todo/v1/todos/:id`
- 入力：パスの id（1以上の整数）、本文 `{ "completed": true | false }`。
- 結果：200 で更新後の TODO を `{ "data": { ... } }` で返す。
- エラー：id 不正・本文不正 400、値の型が不正 422、該当なし 404、500、503。
- 受け入れ条件：チェックを切り替えると完了状態が変わり、再読み込みしても保持されること。存在しない id は 404 になること。
- 確認方法：画面でチェックして再読み込みする。存在しない id（例：999999）に PATCH する。
- 備考：完了状態だけ更新するため PUT ではなく PATCH を使う。タイトル更新は作らない。

### REQ-04 TODO を削除する
- 操作：削除ボタン／`DELETE /api/todo/v1/todos/:id`
- 入力：パスの id（1以上の整数）。
- 結果：204、本文なし。
- エラー：id 不正 400、該当なし 404、500、503。
- 受け入れ条件：削除した TODO が一覧から消え、再読み込みしても戻らないこと。
- 確認方法：画面で削除して再読み込みする。存在しない id を DELETE して 404 を確認する。

## 3. 共通のデータ・エラー条件

- データ項目：`id`（整数・自動採番）、`title`（1〜100文字、必須）、`completed`（真偽値、初期値 false）、`created_at`（作成日時）。
- 成功 JSON：`{ "data": ... }`（一覧は配列、単体はオブジェクト）。
- エラー JSON：`{ "error": { "code": "...", "message": "..." } }`。
- ステータス：400（リクエスト形式不正）、422（入力値が制約違反）、404（対象なし）、500（サーバ内部エラー）、503（DB 接続不可）。
- GET は DB を変更しない。DELETE を繰り返しても最終状態は同じ。

## 4. 環境別の確認方法

| 環境 | 確認方法 |
|---|---|
| ローカル | `npm run dev` → `http://localhost:3000/todo`、`/api/todo/v1/todos` |
| Vercel Preview | PR で作られた Preview URL の `/todo` で REQ-01〜04 を確認 |
| Vercel Production | main マージ後の公開 URL の `/todo` で REQ-01〜04 を確認 |

- どの環境でも `/api/db-check` が `ok: true` を返すこと。
- Preview と Production は同じ DB のため、確認で作ったデータは確認後に削除する。

## 5. 対象外（V1 では作らない）

認証・ログイン、優先度、絞り込み・検索、タイトル更新、個人情報の保存、スマホ最適化。（優先度・絞り込みは V2）
